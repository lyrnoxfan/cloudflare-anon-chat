# Android 客户端与网页基线对照

基线是仓库当前 `public/index.html`、`public/style.css`、`public/app.js` 和 `public/call.js`。旧截图不作基准；当前网页主题为浅绿/暖白，Android 是原生 View 客户端，目标是覆盖同一使用流程并匹配移动端主要结构，而非逐像素复刻网页 DOM。

## 故障诊断与本轮修复

三方 SFU 失败 run `40844376669` 对应 `a14b0ff5e967ae7061b0df8e484c16db2a622997`。保留的 instrumentation 结果为：`远端媒体连接失败，请重新加入：媒体连接超时，请检查网络或 TURN 配置`，且最后状态是 `正在重新连接远端媒体：媒体连接超时...`；这把故障定位到 Android 的远端订阅/重建路径，而不是证明房间创建、UI 或服务端部署故障。该版本订阅端 `awaitConnected` 只有 12 秒；网页 `connected()` 等待 20 秒，Android 发布端本来也等 20 秒。把订阅等待统一为 20 秒，并在已连接的发布端进入 `FAILED` 或持续 `DISCONNECTED` 6 秒时触发群组通话有界重加入。此次失败资料没有可用的 ICE candidate、选路或 SFU 端逐请求日志，所以无法断言底层网络/TURN 根因；这一改动解决的是可证实的客户端超时窗口不一致，最终同提交验收结果决定正常通话是否恢复。

## 本轮一并修改

- 版本为 Android 0.3.1。多人通话视频格按参与者行数和窗口高度限高，缩小通话区域时仍给聊天内容留空间；旋转或窗口尺寸变化时重新计算。
- 表情面板随可用视口缩高，超出部分由可滑动网格承载；Activity 验收增加边界检查和实际滑动，确认能看到新的表情项。
- 房间图标、移动聊天间距及三方轨道/名称已在前序已纳入的同一分支基线上；本轮不以这些单点功能替代整体对照或集中验收。
- SFU 验收会在通话仍持续时，对三台模拟器施加 150 ms 网络延迟和上下行各 2 Mbps；检查两条 PeerConnection 仍为 connected、每端视频字节继续增长。此前 `05061c2` 的约束网络检查因 owner 收包计数未增长而失败，但失败工件没有保存收发计数或 ICE 状态，不能判断是音频停流还是模拟器音源没有发包。现补充逐端收发计数与连接状态证据；仅当至少一个远端发布端在窗口内发送音频字节，才要求接收端音频包增长；若无发送音频，则明确将该窗口的音频连续性记为未验证，不把无源音频误判为传输失败，也不宣称已验证。该模拟器约束不证明丢包、断网或恢复能力。

- 在 `NativeCallSession` 的 SDP、ICE 收集和连接等待中增加定期 `call-heartbeat`，避免同步媒体协商长时间占住串行轮询线程而延误 45 秒成员租约续期。此改动针对代码中的租约饥饿风险，不解释也不掩盖已观察到的 ICE `FAILED`；需由最终三方 SFU 验收确认，仍保留原媒体断言。

## 流程对照矩阵

| 网页流程 | Android 路径 | 覆盖/差异 |
|---|---|---|
| 匿名会话、昵称、授权错误与会话恢复（`app.js`） | 原生会话门、API cookie、错误及刷新状态 | 本地服务 + Activity 验收覆盖选定流程；不是生产服务、真实账户或所有会话状态的验证 |
| 大厅/私人房：建房、口令加入、成员、房号/链接（`index.html`, `app.js`） | 房间抽屉、表单、成员列表、复制邀请 | 行为入口对应；Android 原生对话框与网页 `<dialog>` 的布局、系统返回行为不同 |
| 实时消息、历史分页、重连/补同步、删除（`app.js`） | OkHttp WebSocket、原生列表、历史/状态同步 | 隔离本地服务与 Activity 场景覆盖；长时间断连、多网络切换后的端到端一致性仍不等于已证 |
| 文本发送、重试、引用/复制/删除、表情资源（`app.js`） | 原生 composer、长按菜单、回复草稿、资源内置的表情滚动网格 | 重点交互由 Activity 测试；系统输入法、无障碍焦点和菜单视觉遵循 Android，不完全同构 |
| 图片预览、视频内联/放大、音频控件、附件（`app.js`） | 原生查看器、播放器、文件选择器、授权下载及保存 | 本地夹具检查 API 和保存/播放动作；下载后播放不同于网页直连媒体，设备编解码器、真实网况仍需设备验证 |
| 语音录制、预听、发送/取消（`app.js`） | 原生权限与 `MediaRecorder` | 模拟器可覆盖控件/资源生命周期，不证明实体麦克风的音质、权限弹窗或耳机音频路由 |
| 一对一/多人通话、邀请/接听/拒绝、静音、相机控制、挂断（`call.js`） | `NativeCallSession` WebRTC/SFU 与 Activity 通话视图 | 三台模拟器验收可证明三位参与者及每端两路远端视频、标签与控件；不证明真机体验。网页在断线时最多两次 leave/rejoin；Android 现对已建立的发布端检测 FAILED 或持续 DISCONNECTED（6 秒），并对群组通话最多自动 leave/rejoin 两次；当前 Android 订阅连接等待从 12 秒延长至与网页相同的 20 秒，另保留远端订阅重建。最终测试若通过，只证明正常三方连接，不会验证丢包/断网后的恢复逻辑 |
| 通话视频格与小窗口布局（`style.css`，`#videos` / `46vh` 上限） | 原生两列参与者网格 | 本轮按行数/高度动态限高，保留聊天区；字体、裁切和比例仍取决于原生布局与设备屏幕，不宣称像素一致 |
| 当前色板与聊天页面尺寸（`style.css`） | 当前浅绿/暖白资源、已做的移动顶栏/消息/输入栏间距、房间图标 | 以现行 CSS 为准；系统状态栏、安全区域、字体字重和导航栏不同，完整页面视觉对齐仍未逐项证明 |
| 前后台、锁屏及音频焦点 | Activity 生命周期释放媒体采集，显式音频焦点处理 | 无锁屏凭证的 CI 模拟器检查息屏/Home 资源释放；并非真机安全锁屏、厂商后台策略或蓝牙耳机验证 |
| 内部实现方式 | 网页 JavaScript/DOM | Android 为 Java/Kotlin 原生界面、网络与 WebRTC；C++/JNI 只用于现有辅助状态/校验逻辑，架构并非与网页相同，也未实现完整 C++ 媒体/客户端核心 |

## 尚未证实的边界

CI 当前可用的是 Android 10 x86_64 模拟器；执行环境没有 ADB、USB 连接或真实音频设备。关闭实体设备差距需要在指定型号/Android 版本上安装与本报告 SHA-256 对应的 APK，记录权限流程、双方音视频和通话日志，并实际选择听筒/扬声器/蓝牙路由。CI 模拟器可通过 Emulator Console 限制延迟和带宽；本轮自动重连代码尚需真实断网或丢包注入才能验证恢复行为；三方 SFU 验收只证明正常通话和延迟/带宽限制期间媒体持续流动，不应被解释为恢复机制已实测。CI 仍不验证实体设备的麦克风、摄像头、听筒/扬声器/蓝牙路由或真实弱网体验。

Cloudflare Worker、Durable Objects、D1、R2 的生产部署及配置均不在本轮操作范围，未改动或部署。

最终提交 SHA、两条集中验收运行、实际测量结果及随包文件见 `G29-ACCEPTANCE.md`。

#### 附件传输跟进（当前实现，待集中验收）
- Android 附件发送现在补上与网页一致的进度显示、PUT 上传取消及失败重试。失败后保留本地快照并复用同一上传授权/client id；确认接口具幂等性，重试不重复创建消息。进入确认阶段后禁用取消，因为服务端可能已经提交。
- 上传前按网页分类与限制检查文件大小（图片及语音 10 MiB、视频 100 MiB、其他文件 50 MiB；参数化 MIME 也归一化处理），并将 Ogg 视频识别为视频。
- 隔离服务集成验收增加进度到达文件长度、重复确认返回同一消息 id、取消的授权不能再确认三项检查，须在最终提交的整轮构建/验收中验证。
